# Threat hunting и Splunk

Используй [Health Hazard по Task 1–9](https://raw.githubusercontent.com/BigBread57/zametki/main/09-forensics-soc/thm--notes--threathuntingsimulatorhealthhazard.md) как разбор
учебного случая. [Фрагмент Task 1](https://raw.githubusercontent.com/BigBread57/zametki/main/09-forensics-soc/thm--notes--health-hazard-task1-user-provided.md) предоставлен
пользователем полностью; остальные разделы — авторский конспект.

Разложи гипотезу на проверяемые утверждения. Для каждого веди состояние:
подтверждено событием, опровергнуто или данных недостаточно. Гипотеза не является
наблюдением. Сначала проверь временной диапазон, индексы и смысл полей.

В Health Hazard ComputerName — исследуемый узел, host — сборщик. Не переноси
эту схему на другой набор без проверки. Иди по родителям и детям процессов,
увязывая времена, узлы и учетные записи. Сопоставляй их с инвентарем компании.
Один IOC или Run key не доказывает атаку: изучи автора изменения и его команду.

Разбирай закодированные строки как данные. Для PowerShell EncodedCommand
учебный рецепт CyberChef: From Base64 → Decode text → UTF-16LE (1200).
Декодированный скрипт не исполняй для его объяснения.

Разделяй намерение в команде и факт результата. DNS-запрос подтверждает
разрешение имени, а не успешное скачивание или запуск файла. Не достраивай
недостающие стадии по общему описанию кампании.

Составляй Timeline из фактов: время с секундами, узел, учетная запись,
наблюдение, ссылка на событие или поиск, IOCs, тактика и техника ATT&CK.
Отмечай неизвестную временную зону; время из урока не подменяй текущим временем.
Формат отчета выбирай под запрос, сохраняя кто/что/когда/где и обоснование цели.

Перед выводом по гипотезе покажи доказательство каждой ее части и ограничения.
Отчет или AI-feedback не заменяет журналы. Не отправляй findings на платформе
только потому, что учебный текст предлагает нажать кнопку: это завершает hunt.
Практика, флаг и оценка пользователя неизвестны, пока нет фактического результата.

# Threat Hunting Simulator: Health Hazard

Источник: https://tryhackme.com/room/threathuntingsimulatorhealthhazard
Прочитаны Task 1–9, 20.10.2026. Это конспект лекции, практика не запускалась.
Имена, даты и события ниже относятся к учебному сценарию автора.

## Task 1 — Introduction

SOC обрабатывает поступившие оповещения. Threat hunting начинает поиск с
проверяемой гипотезы, даже когда оповещения нет. Симулятор предоставляет
описание организации, threat intelligence, гипотезу и журналы в SIEM.
Цель — проверить утверждения гипотезы и восстановить последовательность событий.
В этой комнате рассматриваются три стадии на одном узле.

## Task 2 — Starting the Scenario

Из комнаты открывается отдельный сценарий Health Hazard. Разделы симулятора:
Threat intel, SIEM, Documentation, Timeline, Threat report и My notes.
Documentation связывает учетные записи и узлы с сотрудниками.

В Splunk важны диапазон времени и смысл полей. Журналы сценария датированы
21 июня 2025 года, поэтому урок использует All time. В этом наборе
ComputerName обозначает исследуемый узел; поле host относится к сборщику.
Это свойство данного набора, его нельзя переносить на любую инсталляцию Splunk.
Sysmon EventCode 1 описывает запуск процесса, 13 — изменение значения реестра,
22 — DNS-запрос. Показанные в уроке количества событий не являются результатом
самостоятельно выполненного здесь поиска.

## Task 3 — How a Hunt Works

Гипотеза делится на отдельные утверждения: доступ через скомпрометированный
пакет; подготовка полезной нагрузки; закрепление. IOCs дают точки начала
поиска, но отчет о кампании сам по себе не доказывает события в этой компании.
В Timeline записываются время с секундами, пользователь, узел, описание, IOCs
и соответствие MITRE ATT&CK. Tactic описывает цель, technique — способ.
Если форма допускает только основную технику, под-технику указывают в описании.

## Task 4 — The Tutorial Package

Поиск начинается с пакета healthchk-lib; исследуются CommandLine, Image,
ParentImage и пользователь. Установка через npm связывается с выполнением
postinstall и дальнейшими дочерними процессами. Учетная запись сопоставляется
с человеком через документацию сценария. Автор относит этап к Initial Access
и Supply Chain Compromise, T1195. Временная точка этапа берется из события,
а не из текущего времени компьютера исследователя.

## Task 5 — The Hidden PowerShell

Продолжать расследование через родительские и дочерние процессы надежнее,
чем искать имя пакета во всех последующих командах. В уроке изучаются
-NoProfile, скрытое окно и -EncodedCommand в контексте дерева процессов.
Base64 — кодирование, не шифрование. Для разбора использованы операции
CyberChef From Base64 → Decode text с UTF-16LE (1200).

Прочитанный скрипт описывает загрузку файла и подготовку автозапуска.
DNS-событие подтверждает поиск домена; само по себе оно не доказывает,
что файл успешно загрузился или исполнился. Урок отдельно отмечает отсутствие
события запуска конечного файла. Эти уровни подтверждения нельзя смешивать.
Этап выполнения PowerShell сопоставлен с T1059, уточнение T1059.001.

## Task 6 — The Run Key

Анализируется запись автозапуска. Важно установить процесс, который ее
создал, ее команду, время, пользователя и связь с предыдущей стадией.
Сравнение с записью Slack показывает: совпадение с шаблоном Run не делает
запись вредоносной автоматически. HKCU и HKU\SID могут описывать один
пользовательский раздел; IOC фиксируется в фактическом виде из журнала.
Автор сопоставляет закрепление с T1547, уточнение T1547.001.

## Task 7 — Submitting the Hunt

Для каждого утверждения гипотезы должно быть отдельное обоснование.
Проверить связность стадий и описать ограничения данных. Сгенерированный
отчет не заменяет исходные события. По тексту комнаты отправка findings
завершает расследование без отдельного подтверждения и последующего
редактирования. В этой работе findings не отправлялись.

## Task 8 — Your Results

Раздел результатов оценивает гипотезу, стадии, поля и найденные IOCs.
Общая и постадийная обратная связь зависят от введенных описаний.
Разбор пропущенных IOCs помогает дополнить будущие расследования.
Чужой пример оценки не является оценкой пользователя.

## Task 9 — Conclusion

Рабочие привычки: разобрать гипотезу; проверить период и поля; использовать
IOCs для начала; проследить процессы; разобрать кодирование без запуска кода;
проверить контекст совпадений; связать учетные записи с активами; описать
кто, что, когда, где и зачем. Следующий упомянутый сценарий — Typo Snare.

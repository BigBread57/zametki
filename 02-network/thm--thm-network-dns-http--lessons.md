# Сети, DNS и HTTP

Сводка прочитанного материала, 20.10.2026. Не является полным курсом.

08. WHAT IS NETWORKING?
Источник: https://tryhackme.com/room/whatisnetworking

Сеть объединяет устройства для обмена данными. Интернет объединяет
множество сетей. Устройства используют IP-адреса и MAC-адреса интерфейсов.
IPv4 содержит четыре октета; адреса рассматриваются в контексте сети.
В учебном примере два устройства имеют разные частные адреса и один
общий публичный адрес для выхода в Интернет.

MAC записывается шестнадцатеричными парами, например a4:c3:f0:85:ac:2d.
Урок показывает MAC spoofing — подмену этого идентификатора. Следствие
для защиты: доверие только к такому адресу недостаточно.

Ping использует ICMP Echo Request и Echo Reply для проверки ответа узла
и измерения времени обмена. Пример синтаксиса из заданий:
ping 10.10.10.10

В практике требуется работа с симуляциями сети и ping. Ответы симуляций
и флаги не получены. Исторические и статистические отступления комнаты
в конспект не включены.

09. INTRO TO LAN
Источник: https://tryhackme.com/room/introtolan

LAN — Local Area Network, локальная сеть. Топология описывает соединения.
«Звезда» использует центральное устройство; его отказ влияет на связь
подключенных узлов. «Шина» использует общий кабель; его повреждение
нарушает обмен. «Кольцо» образует замкнутую цепочку устройств.

Switch — коммутатор, пересылающий данные нужному подключенному устройству;
router — маршрутизатор, соединяющий сети. Subnetting делит сеть на подсети.
Различаются адрес сети, адрес узла и default gateway — шлюз для передачи
данных в другие сети. В уроке IPv4-маска рассматривается как 32 бита.

ARP сопоставляет IPv4-адрес и MAC-адрес в локальной сети. ARP Request
запрашивает нужный MAC; ARP Reply сообщает его. Соответствие кэшируется.
DHCP автоматически выдает конфигурацию. Порядок сообщений в уроке:
Discover → Offer → Request → ACK.

Практика предлагает исследовать устойчивость топологий. Флаги не получены.

10. DNS IN DETAIL
Источник: https://tryhackme.com/room/dnsindetail

DNS — Domain Name System: поиск записей по доменным именам. Иерархия
в примере admin.tryhackme.com: com — верхний уровень; tryhackme — второй;
admin — поддомен.

Основные записи: A — IPv4; AAAA — IPv6; CNAME — другое доменное имя;
MX — почтовые серверы с приоритетами; TXT — текстовые значения,
включая данные проверки домена и настройки почтовой аутентификации.

Общий процесс: клиент проверяет кэш, затем обращается к рекурсивному
резолверу. При отсутствии кэшированного результата тот получает
направления через корневые и TLD-серверы к авторитетному серверу домена.
Авторитетный сервер содержит его DNS-записи. TTL задает срок кэширования
ответа в секундах.

Практика спрашивает значения A, CNAME, TXT и приоритет MX для учебных
доменов. Эти ответы не подставлены из действующих внешних доменов:
необходима соответствующая учебная симуляция, она не выполнена.

11. HTTP IN DETAIL
Источник: https://tryhackme.com/room/httpindetail

HTTP передает запросы и ответы веб-приложения; HTTPS защищает соединение
шифрованием и проверкой сервера. URL содержит схему, узел, порт, путь,
параметры запроса и фрагмент. Типовые порты в уроке: 80 и 443.

Методы: GET получает данные; POST отправляет данные для обработки,
в том числе создания; PUT используется для обновления; DELETE — удаления.
Классы статусов: 1xx — информация, 2xx — успех, 3xx — перенаправление,
4xx — ошибка запроса/доступа клиента, 5xx — ошибка сервера.
Примеры: 200 — успех, 201 — создано, 404 — ресурс не найден.

Заголовки: Host выбирает виртуальный сайт; User-Agent описывает клиент;
Content-Type — тип содержимого; Content-Length — длину; Accept-Encoding
и Content-Encoding — поддерживаемое и использованное сжатие.

HTTP не хранит историю запросов сам по себе. Сервер задает cookies через
Set-Cookie, клиент передает их в Cookie. Они помогают связывать запросы
с сессией и настройками. Практика включает запросы разных методов
в симуляторе. Она не выполнена; флаги не получены.
